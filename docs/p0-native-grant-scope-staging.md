# Native grant scope — unreleased P0 correction, 25 November 2026

Browser Core connects Chrome tabs you explicitly authorize to ChatGPT or Claude for actions on websites. For example, if an assistant is preparing a supplier order in a shared tab and the browser reconnects, a queued command must not silently run against a replacement tab or connection. Share only the required tab via the extension popup. This correction blocks queued commands when their original grant changes, and reports a late result from a replaced grant as uncertain rather than success. Inspect the actual tab before deciding whether to repeat an action.

**Staging only:** local branch `p0-native-grant-scope-0739`, base `54908cb`, code commit `c3965a6`. Not included in attended 0.7.28 or signed 0.7.27. The check binds the command to the original native peer, tab ID, grant timestamp, origin and parent handle. Normal same-scope grant announcements remain supported. No new permissions, file access, submission, focus control or automatic retry. This does not cancel already dispatched operations, establish per-assistant isolation, or verify a site's server-side submission.

**Verification:** 3 of 4 new native-peer simulation cases failed before the fix; all 4 passed after. Full Python discovery: 99/102 passed (including 27 isolated Chromium fixture cases); the three failing historical 0.7.24 updater cases also fail on the unchanged parent, with `EXTENSION_PERMISSIONS_CHANGED` in the upgrade case. All 66 JavaScript cases passed. Real installed-extension reconnect, multi-client ownership and signed-update acceptance remain pending. No production code, packages, signing or running owner profiles changed.

**Demand evidence:** [agent-browser #1530](https://github.com/vercel-labs/agent-browser/issues/1530), 11 July 2026 (closed): concurrent sessions could lose their tab binding. [Playwright #42015](https://github.com/microsoft/playwright/issues/42015), 28 July 2026 (closed as duplicate): request for independent clients in an authenticated Chrome profile. These reports support isolation as a reliability requirement; their mechanisms differ from this locally reproduced native queue defect. Alternatives are distinct browser profiles/contexts or official site APIs where offered. Baseline P0 safety, not a separate paid feature; no willingness to pay verified.
